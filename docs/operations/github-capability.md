记录**未被平台强制**的文档约定。本表与 [`../agent-collaboration.md`](../agent-collaboration.md) §6 一致。

| 文档约定 | 平台是否强制 | 说明与补救 |
| -------- | ------------ | ---------- |
| 禁止直接推送默认分支 | **否** | 配置「要求合并前必须经过 PR」后转为强制 |
| 合并前必须通过必需检查 | **否** | 配置必需检查后转为强制 |
| 实现者 ≠ 批准者 | **否**（单一平台身份） | 换会话审查 + `TASK.md` 的 `Known Issues` 披露 + 证据落 `handoffs/` |
| 合并前必须经过实质审查 | **否** | 审查证据必须落到 `handoffs/` |
| 提交信息 / 分支命名规范 | **否** | 由约定与后续自动化检查承担 |
| 合并不得产生对外发布 | **是** | 由仓库内的 `docker.yml` 触发配置保证（tag-only），**不依赖平台设置**；平台无从绕过一个不存在的触发器。实测见 §4 |
| 高风险操作需人类批准 | **否** | 制度门禁 |

> **固定披露项：** 平台审计**无法区分**「执行位的自我确认」与「主控位的独立审查」，

## 8. 平台事实漂移记录

平台设置可以**在版本控制之外被改动**，且改动不会留下任何可追溯的证据
（个人账号的审计日志不通过 API 开放）。因此本文中任何**可变事实**都属于易腐信息，
跨会话引用前应重新实测。下表记录已发现的漂移。

| 事实 | 原记录（阶段 1 调研，附原始输出） | 实测值（2026-10-14） | 影响 |
| ---- | --------------------------------- | -------------------- | ---- |
| `has_issues` | `false`（Issues 关闭） | **`true`** | 阶段 1 问题清单 P-01「Issue 载体不可用」不再成立。**D2 决策不变**，但其理由须改写为「避免双写 + 独立 clone 后任务状态仍完整」，而**不能**再引用「Issues 不可用」 |
| `gh` 身份 | `ndldsn`（对本仓库 `pull` 只读） | **`huyanluanyuqaq`**（`admin: true`） | §6「`gh` 不可用」的结论作废；「由 Agent 创建 / 合并 PR」的阻塞解除 |

**漂移的取证方法：** 同一批读取中 `has_projects` 与 `has_wiki` 与阶段 1 记录**逐项一致**，
仅 `has_issues` 不同——**逐字段对照**才能区分「设置被改动」与「当初读错」。
只对比单一字段会得出错误结论。

**复核命令（引用本文件前请重跑）：**

```bash
gh api repos/huyanluanyuqaq/shadcn-admin \
  --jq '{has_issues, has_projects, has_wiki, has_discussions, private, permissions}'
```

**结论：** 能力记录的价值取决于**新鲜度**，而新鲜度无法靠文档自身保证。
这是「制度 ≠ 平台」在**时间维度**上的表现：不仅「计划的配置」不等于「已生效的配置」，
**「上个月实测过的配置」同样不等于「今天的配置」**。

> **自锁风险提示：** 若同时启用「要求状态检查通过」与「不允许绕过」，
> 而某次提交破坏了 `ci.yml` 自身（YAML 非法 → 检查永不上报），
> 则「合并被阻」与「直推被阻」同时成立，**无法用常规手段修复 `main`**，
> 唯一逃生是所有者从网页端修改或停用规则。
