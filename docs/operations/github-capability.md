## 5. 制度-平台落差披露

记录**未被平台强制**的文档约定。本表与 [`../agent-collaboration.md`](../agent-collaboration.md) §6 一致。

| 文档约定 | 平台是否强制 | 说明与补救 |
| -------- | ------------ | ---------- |
| 禁止直接推送默认分支 | **否** | 配置「要求合并前必须经过 PR」后转为强制 |
| 合并前必须通过必需检查 | **否** | 配置必需检查后转为强制 |
| 实现者 ≠ 批准者 | **否**（单一平台身份） | 换会话审查 + `TASK.md` 的 `Known Issues` 披露 + 证据落 `handoffs/` |
| 合并前必须经过实质审查 | **否** | 审查证据必须落到 `handoffs/` |
| 提交信息 / 分支命名规范 | **否** | 由约定与后续自动化检查承担 |
| 高风险操作需人类批准 | **否** | 制度门禁 |

> **固定披露项：** 平台审计**无法区分**「执行位的自我确认」与「主控位的独立审查」，
> 因为两者在审计记录中是同一个平台身份。

## 6. 自动化能力现状

| 能力 | 现状 | 前置条件 |
| ---- | ---- | -------- |
| Git 分支 / 提交 / 推送 | **可用**（SSH 身份为仓库所有者） | — |
| Actions 运行 CI | **可用**（已在 `push main` 与 `pull_request` 上运行） | — |
| `gh` CLI 创建 / 合并 PR | **不可用**（实测：`permissions` 为 `pull: true, push: false, admin: false`；`gh pr create` 返回 `GraphQL: must be a collaborator (createPullRequest)`） | 以仓库所有者身份重新认证，或改用浏览器操作 |
| 读取仓库 / 运行记录 | 可用（只读凭据） | 只读凭据 |
| 修改分支保护 / 规则集 | **不可用** | 管理员权限 + 网页端操作 |
| 由平台事件自动触发本地 Agent | **否** | 需可达的 Agent 运行时（本项目未建设） |
| 受控自动合并 | **否** | 保护 + 必需检查 + 合并与发布解耦 |

**当前自动化级别：** Level 1（手动协作）

> **注意「Git 推送可用」与「`gh` 不可用」并不矛盾**：二者使用的是**不同的凭据**。
> 推送走 SSH 密钥（仓库所有者）；`gh` 走 OAuth token（另一个身份，对本仓库只有只读权限）。
> 因此「Agent 能推分支」**不意味着**「Agent 能创建 PR」。

> **自锁风险提示：** 若同时启用「要求状态检查通过」与「不允许绕过」，
> 而某次提交破坏了 `ci.yml` 自身（YAML 非法 → 检查永不上报），
> 则「合并被阻」与「直推被阻」同时成立，**无法用常规手段修复 `main`**，
> 唯一逃生是所有者从网页端修改或停用规则。
