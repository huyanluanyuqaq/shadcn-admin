# requirements — 需求文档

存放项目的需求定义。由 **Product** 角色维护。

## 内容

| 文件 | 内容 |
|------|------|
| `overview.md` | 项目整体需求概览（目标、用户、场景） |
| `{{feature-name}}.md` | 单个特性的需求文档 |

## 需求文档模板

见 `_template.md`。

## 写作要求

- **目标明确**：要解决什么问题，为谁解决。
- **边界清晰**：Scope / Non-Scope 必须写明。
- **验收标准可判定**：每条能用"是/否"回答。
  - ❌ "用户体验要好"
  - ✅ "登录失败 5 次后锁定账户 15 分钟"
- **不指定技术实现**：那是 Architect 的职责。

## 与 Task 的关系

需求文档是 Task 的**上游**。一个需求可拆分为多个 Task。
Task 的 `TASK.md` 中 `Acceptance Criteria` 应引用或派生自需求文档。
