# Agent Constraints — 受保护约束（内嵌）

> ⚠️ **本文件属于受保护内容（Protected Content）。**
> 任何 Project 规则、Task 规则、目录级规则**不得削弱**本文件中的任何约束。
> 本文件的存在是为了保证：**项目脱离 Workspace 独立运行时，核心安全约束仍然有效。**
>
> 在 Workspace 模式下，完整规则以 `.agents/rules/security.md`、
> `.agents/protocols/change-safety.md` 与 `.agents/protocols/permissions.md` §3 P3
> 为准；本文件是其**要点摘要**。

---

## 1. 敏感信息（绝对禁止）

以下内容**绝对禁止**出现在代码、日志、提交、文档中：

- 密码、API Key、Token、私钥、证书
- 个人数据（身份证号、手机号、地址、生物特征）
- 生产连接串、生产端点、内部主机名

**做法：** 通过环境变量或密钥管理服务注入；提交前扫描。
**若已泄露：** 立即**轮换**（仅从历史删除不够）。

---

## 2. 最小权限

- 默认拒绝（deny by default）。
- 只授予完成任务所必需的权限。
- 不扩大权限以"方便实现"。
- 不自我提权。

---

## 3. 输入不可信

- 所有外部输入都必须校验（类型、长度、范围、格式、白名单）。
- 禁止将未校验输入拼接进查询、命令、路径、模板（防注入）。

---

## 4. 高风险操作流程（强制）

以下操作属于**高风险**，必须走完整流程：

```
Inspect → Explain → Backup → Approval → Modify → Verify
```

**高风险清单：**

- 删除数据 / 删除文件
- 数据库迁移 / 结构变更
- 修改生产环境
- 修改安全策略
- 修改基础设施
- 大规模重构
- Destructive Git 操作（`push --force` / `reset --hard` / `clean -fdx` / 历史重写）

**关键要求：**

1. 修改前**必须**备份，且验证备份可用。
2. **必须**获得人类显式批准（针对本次具体变更）。
3. **必须**有回滚方案。
4. 无备份 → 不得进行不可逆变更。

---

## 5. 删除文件约束

- ❌ 禁止递归删除用户个人目录（Desktop / Downloads / Documents / Home）。
- ❌ 禁止 `rm -rf` 作用于宽泛路径（`/`、`~`、`C:\`）。
- ✅ 优先使用可恢复方式（版本控制 / 回收站）。
- ✅ 批量删除先列清单，分批执行（每批 ≤ 10），每批后验证。
- ✅ 删除前确认路径精确无误。

**个人目录扫描：** 默认**只读**，只产出报告，不执行修改。

---

## 6. Git 禁止操作

- ❌ 提交密钥、令牌、密码、证书
- ❌ 在共享分支上强制推送
- ❌ 未经确认删除他人分支
- ⚠️ `reset --hard` / `clean -fdx` 需先预演确认

---

## 7. 测试约束

- ❌ 不得为了通过而删除/跳过测试
- ❌ 不得弱化断言
- ❌ 不得把"未测试"报告为"通过"
- ✅ 缺陷修复必须附带一个"修复前失败、修复后通过"的测试

---

## 8. 职责分离（Agent 协作）

以下三对**不得由同一个 Agent 承担**：

| 分离对 | 防止 |
|--------|------|
| 实现者 ≠ 批准者 | 自我批准 |
| 修复者 ≠ 验证者（关键路径） | 自证 |
| 部署者 ≠ 安全审批者 | 绕过安全 |

- 同一时刻，一个 Agent 只能扮演一个 Role
- 角色切换**必须**写 Handoff（即使前后是同一个 Agent）
- 只有 1 个 Agent 可用时 → 换**全新会话**审查；无法换会话则该任务不得标记完成
- 完整分配方案见 `.agents/protocols/role-assignment.md`

---

## 9. 安全默认姿态

| 维度 | 默认 |
|------|------|
| 访问控制 | 拒绝 |
| 输入 | 不可信 |
| 数据 | 加密 |
| 日志 | 脱敏 |
| 权限 | 最小 |
| 失败 | 关闭（fail-closed） |

---

## 10. 不确定时

> **若不确定某操作是否高风险 —— 按高风险处理。**
> **若不确定是否有权限 —— 停下来问，不要越权执行。**
