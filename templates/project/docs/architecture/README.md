# architecture — 架构文档

存放系统架构定义。由 **Architect** 角色维护。

## 内容

| 文件 | 内容 |
|------|------|
| `overview.md` | 系统整体架构（分层、模块、数据流） |
| `api.md` | 对外接口契约 |
| `data-model.md` | 数据模型 |
| `{{component}}.md` | 单个组件的详细设计 |

## 架构文档应包含

1. **系统上下文** —— 系统边界、外部依赖
2. **模块划分** —— 各模块职责与边界
3. **接口契约** —— 输入、输出、错误情形
4. **数据流** —— 数据如何流转
5. **关键约束** —— 性能、安全、兼容性

## 写作要求

- **接口必须明确**：输入 / 输出 / 错误 / 边界条件。
- **不写实现细节**：那属于 `technical/`。
- **决策要引用 ADR**：重要的架构选择应链接到 `decisions/`。

## 与 Task 的关系

Architect 在 Design 阶段更新本目录，并通过 Handoff 交给 Developer。
Developer 发现设计不可行时应**回退**，而不是自行修改架构文档。
