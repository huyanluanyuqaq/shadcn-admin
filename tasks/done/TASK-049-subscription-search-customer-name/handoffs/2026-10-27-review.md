### 1.3 代码层（读 HEAD 上的实际代码）

**① OR 单一条件（crud.ts:158-167，实读）：**

```ts
const conditions: SQL[] = []
const keyword = (query.q ?? '').trim()
if (keyword) {
  // 本表 like 条件 + 跨表钩子条件，统一 OR 后作为**单一**条件进入 AND 链——
  // 多个条件分别 push 会因 AND 优先级更高而退化成「必须同时命中」，语义错误。
  const matches: SQL[] = searchCols.map((col) => like(col, `%${keyword}%`))
  const extra = searchCondition?.(keyword)
  if (extra) matches.push(extra)
  if (matches.length > 0) conditions.push(or(...matches) as SQL)
}
```

✅ searchCols like 与钩子条件统一 OR 后作为**单一**条件入 AND 链（`conditions.push(or(...matches))`）；
未拆成多个 push。与原代码对比（`git diff origin/main -- server/src/lib/crud.ts`）：
原 `if (keyword && searchCols.length > 0)` 分支行为在新代码下等价（无钩子且 searchCols 为空时
`matches.length === 0` 不 push）。

**② exists() 关联条件（resources.ts:110-125，实读）：**

```ts
searchCols: [subscriptions.name, subscriptions.url],
searchCondition: (keyword) =>
  exists(
    db.select({ id: customers.id }).from(customers)
      .where(and(eq(customers.id, subscriptions.customerId), like(customers.name, `%${keyword}%`)))
  ),
```

✅ `eq(customers.id, subscriptions.customerId)` 在位（漏掉即恒真，未漏）。

**③ 参数绑定 / 注入面：** 关键字经 `%${keyword}%` 仅在 JS 字符串层拼模式串，随后作为 drizzle
`like()` / `exists()` 构建器的**值参数**入参，全链路无 `sql` 原始模板拼接、无裸 SQL。✅

**④ 其余 5 资源行为不变：** `grep -n 'searchCondition' server/src/routes/resources.ts`
仅 `:114` 一处（订阅）；`crud.ts` 三处均为工厂自身的定义/解构/调用。可选字段 +
`matches.length > 0` 兜底使无钩子时与原代码逐字节等价。✅

**⑤ q 的 trim 与空值行为：** `(query.q ?? '').trim()`；空/空白 q 不产生任何条件（API 实测见 1.5），
不清空其他筛选（filterCols 循环独立于 keyword 分支）。✅
