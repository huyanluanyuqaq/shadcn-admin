# shared — 跨项目共享资源

存放**可以跨项目复用**的资源。

---

## 目录

| 目录 | 内容 |
|------|------|
| `scripts/` | 可复用脚本（如创建新项目） |
| `tools/` | 可复用工具 |
| `knowledge/` | 共享知识（规范、清单、参考资料） |

---

## 允许共享的内容

| 类型 | 示例 |
|------|------|
| 项目脚手架脚本 | `create_project.py` |
| 通用检查工具 | 提交信息校验、密钥扫描 |
| 通用模板 | 会议记录、评审清单 |
| 通用知识 | 编码规范摘要、常见陷阱 |

---

## 严格禁止

| 禁止 | 原因 |
|------|------|
| ❌ 项目源码 | 破坏项目自包含 |
| ❌ 项目专用配置 | 造成隐式依赖 |
| ❌ 密钥 / 凭据 | 安全风险 |
| ❌ 项目文档 | 应在项目内 |

---

## 隐式依赖警告

> **不要让项目之间通过 `shared/` 产生隐式依赖。**

**错误做法：**

```
project-a/src/foo.py  ──imports──→  shared/tools/helper.py
project-b/src/bar.py  ──imports──→  shared/tools/helper.py
```

这会导致：项目脱离 Workspace 后无法运行。

**正确做法：**

- 项目所需的一切代码都在项目自己的 `src/` 内。
- `shared/` 只放**开发期**辅助工具（不参与项目运行时）。
- 若某逻辑确实需要共享，应**发布为独立库**，由项目显式依赖。

---

## 判定标准

放入 `shared/` 前问自己：

1. 这个资源是否与任何具体项目无关？ → 否则放回项目内。
2. 项目运行是否需要它？ → 是的话，它不该在 `shared/`。
3. 删除它会影响项目构建吗？ → 会的话，它不该在 `shared/`。
