# 公共规范 · GitHub 协作

> GitHub 平台协作规则。**技术栈无关。**
> 分支命名与提交信息以 `git.md` 为准，本文件只管**平台协作层**。

---

## 1. 适用范围

适用于以 GitHub 为协作载体的项目。

**前提：** 项目必须在 `AGENTS.md` 中声明是否启用本规则，并提供自己的**平台能力记录**
（见 `docs/capability/` 模板）。未提供能力记录的项目，**不得声称已具备平台门禁**。

---

## 2. 分支

- 命名见 `git.md` §1；提交格式见 `git.md` §2。
- 工作分支从最新默认分支派生，并推送到远端。
- 一个任务一个分支；一个分支只服务一个任务。

---

## 3. 交付请求（Pull Request）

- **所有对默认分支的改动必须通过 PR 合并，禁止直接推送默认分支。**
- PR **必须**关联任务标识。
- 实施期间可用草稿状态，自检完成后再标记可审查。
- **不得只在 PR 里写信息而不回写任务文件。** 两者必须同步。
- 模板：项目侧用 `.github/PULL_REQUEST_TEMPLATE.md`（项目自有，不被框架同步覆盖）；
  字段清单见本文 §3。中央仓的参考模板在 `templates/github/PULL_REQUEST_TEMPLATE.md`。

### PR 描述必填字段

| 字段 | 说明 |
|---|---|
| 关联任务 | Task ID |
| 变更摘要 | 做了什么 |
| 包含范围 / 排除范围 | 明确边界 |
| 测试结果 | 命令 + 结果；**未执行的测试必须写明** |
| 兼容性 | 是否破坏兼容 |
| 回滚方案 | 如何回退 |
| 遗留问题 | 无则写"无" |
| 自检 | 提交前检查清单结果 |

---

## 4. 检查

- 只有**稳定且必要**的检查才设为必需检查。
- 必需检查**必须包含**（项目可按技术栈增补）：

| 类别 | 要求 |
|---|---|
| 静态检查 | 必须 |
| 格式检查 | 必须 |
| 测试 | 必须 |
| 构建 | 必须 |

- 检查**必须在合并之前运行**。若检查仅在合并后触发，则**不构成门禁**，
  项目必须在能力记录中如实标注。
- **禁止**通过删除测试、放宽断言、伪造结果或绕过保护规则使检查变绿。

---

## 5. 合并

合并前必须满足：审查通过 + 必需检查通过 + 分支保护条件满足 + 必要授权。

- 默认策略 `rebase-merge`（覆盖 `git.md` §5 默认值，理由见 `git.md` §5）。
- 合并后删除工作分支。
- 合并后**必须**回写任务文件：状态、PR 号、检查运行号、遗留问题。

### 回写时机（简化后）

| 任务级别 | 回写方式 |
|---|---|
| S / M | **同一 PR 内完成回写**（在合并前把状态改成 `DONE`） |
| L | 同一 PR 内完成回写；若确有跨任务归档需求，由 Coordinator 明确指定承接任务 |

> 已废弃：原 D13-C「由下一个任务回填 Merge Record」机制。该机制导致任务长期滞留
> `review/` 并产生跨任务债务（实测 TASK-055/057/058/059 四轮欠账）。
> 历史档案中的相关记录**不回溯修改**。

---

## 6. 禁止操作（含受保护项）

| 操作 | 原因 |
|---|---|
| 直接推送默认分支 | 绕过交付与检查门禁 |
| 对共享分支强制推送 | 覆盖他人工作（同 `git.md` §6） |
| 未经检查覆盖他人分支的修改 | 丢失工作 |
| **由实现者批准自己提交的 PR** | **违反 I2（受保护）** |
| 由 Agent 或自动化自行批准高风险操作 | 绕过人类授权（受保护） |
| 未获授权时合并、发布或执行破坏性操作 | 越权 |

**绝对禁止：**

- ❌ 提交密钥、令牌、密码、证书
- ❌ 把「未实测的平台配置」描述为已生效
- ❌ 声称平台已强制某项实际未被强制的约定

---

## 7. 平台配置

以下事项**必须**在平台侧单独配置，**不能仅靠提交仓库文件完成**：

- 分支保护 / 规则集（必需 PR、必需检查、禁止强制推送、禁止删除分支、不允许绕过）
- 协作者与权限授予
- 密钥与凭据

配置清单见 `shared/scripts/github_setup_checklist.md`。
配置完成后**必须实测**并记录结论。

> ⚠️ **CODEOWNERS 不能单独提供独立审查。** 它只自动请求审查者，
> 不创建独立身份、不启用审批、不阻止合并。

---

## 与项目规则的关系

项目可在 `AGENTS.md` 中声明：必需检查清单、合并策略（覆盖 §5 需注明理由）、平台能力记录位置。

**下列条目项目不得削弱：** §3 禁止直推默认分支；§6 中与 I2 和人类授权相关的条目；§4 中禁止伪造或绕过检查的条目。
