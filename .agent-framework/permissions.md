# 公共规范 · 权限（Permissions）

> 定义 Agent 的通用权限模型。**按角色授予权限，按风险追加约束。**

---

## 1. 权限维度

| 维度 | 含义 |
|---|---|
| **Read** | 读取文件 |
| **Write** | 修改文件 |
| **Execute** | 运行命令 / 脚本 |
| **Delete** | 删除文件 / 数据 |
| **Network** | 访问网络 |
| **Git** | 执行 Git 操作 |
| **Deploy** | 部署到环境 |

符号：✅ 允许 ｜ ⚠️ 有限 / 需条件 ｜ ❌ 禁止

---

## 2. 三角色权限矩阵

| 角色 | Read | Write | Execute | Delete | Network | Git | Deploy |
|---|---|---|---|---|---|---|---|
| **Coordinator** | ✅ | ⚠️ 任务文件与规范 | ✅ | ❌ | ✅ | ⚠️ 只读为主 | ❌ |
| **Developer** | ✅ | ✅ 源码/测试 | ✅ | ⚠️ | ⚠️ | ✅ 任务分支 | ⚠️ 本地/测试 |
| **Reviewer** | ✅ | ⚠️ 审查记录 | ✅ 验证 | ❌ | ⚠️ | ⚠️ 只读 | ❌ |

---

## 3. 通用权限原则

### P1 — 最小权限

只授予完成任务所必需的权限。不为"方便"扩大权限。

### P2 — 默认拒绝

未明确授予的权限默认为**拒绝**。

### P3 — 🔴 职责分离（受保护规则）

| 分离对 | 原因 |
|---|---|
| 实现者 ≠ 批准者 | 防止自我批准 |
| 修复者 ≠ 验证者（关键路径） | 防止自证 |
| 部署者 ≠ 安全审批者 | 防止绕过安全 |

**这三对属于受保护规则**，任何层级不得削弱。其他角色可以兼任，**分离对不行**。

### P4 — 高风险追加约束

权限**不因角色而无限扩大**。即使角色允许某动作，若属于高风险（见 `change-safety.md`），仍需额外流程。

> 角色权限决定"能不能做"；风险等级决定"要不要走审批"。

### P5 — 🔴 不可自我提权

Agent **不得**修改自己的权限定义。权限定义属于框架层，**修改需人类批准**。

---

## 4. 写权限的边界

`Write ✅` 不等于"可写任意文件"。写权限始终受以下约束：

1. **File Scope** —— 仅限任务声明的范围。
2. **角色边界** —— 仅限该角色的职责产物（如 Coordinator 不写业务代码）。
3. **受保护规则** —— 不得削弱 `quality.md` §三 等。

---

## 5. 删除权限

**删除是最危险的操作。**

- 默认 ❌ 或 ⚠️，而非 ✅。
- 删除文件 → 优先使用可恢复方式（版本控制 / 回收站）。
- 删除数据 → 必须走 `change-safety.md` 高风险流程。
- **禁止**递归删除用户个人目录（Desktop / Downloads / Documents / Home）。
- **禁止** `rm -rf` 作用于宽泛路径。

## 6. 网络权限

| 场景 | 权限 |
|---|---|
| 读取公开文档 | ✅ |
| 下载已声明的依赖 | ✅ |
| 上传代码 / 数据到外部 | ⚠️ 需说明 |
| 访问生产系统 | ❌ 除非明确授权 |
| 发送外部消息（邮件/Webhook） | ⚠️ 需人类确认 |

---

## 7. Git 权限

| 操作 | 权限 |
|---|---|
| `status` / `diff` / `log` | ✅ |
| `add` / `commit`（任务分支） | ✅ |
| `push`（任务分支） | ✅ |
| `merge` 到 main | ⚠️ 需审查通过 |
| `push --force` | ❌ 受保护规则禁止 |
| `reset --hard` / `clean -fdx` | ⚠️ 高风险，需批准 |
| 删除分支 | ⚠️ 需确认已合并 |

---

## 8. 部署权限

| 环境 | 权限 |
|---|---|
| 本地 | ✅ |
| 开发 / 测试 | ✅ |
| 预发 | ⚠️ 需批准 |
| 生产 | ❌ 默认禁止；需**人类显式批准** |

---

## 9. 不确定时怎么办

1. **不要假设有权限。**
2. 查阅本文件 + 对应角色定义。
3. 仍不确定 → **停止并请求人类裁决。**

> 宁可停下来问，也不要越权执行。

---

## 10. 越权后果

越权可能导致数据丢失、安全漏洞、协作状态损坏、不可逆的历史改写。
越权被视为**严重违规**，必须记录并复盘。
