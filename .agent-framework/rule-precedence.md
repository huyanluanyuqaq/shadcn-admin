# 公共规范 · 规则优先级

> 定义规则的继承与冲突裁决机制。**这是框架最核心的协议之一。**

---

## 1. 问题

规则分布在多个层级。当不同层级给出**冲突**要求时，必须有确定的裁决规则。
朴素的线性继承（"最具体的总是获胜"）有缺陷：**它允许低级规则削弱安全约束。**

---

## 2. 双轴模型

### 轴 A — 约束轴（受保护规则）

| 受保护规则 | 位置 |
|---|---|
| 安全约束 | `quality.md` §三 |
| Git 禁止操作 | `git.md` §6 |
| 测试禁止事项 | `quality.md` §二 §5 |
| 职责分离（实现者 ≠ 批准者） | `permissions.md` §3 P3 · `collaboration.md` §1 I2 |
| 高风险操作流程 | `change-safety.md` |
| GitHub 侧对应禁止项 | `github.md` §6 |

**为什么"职责分离"在表内：** 它约束的不是"能不能做"，而是"**谁来做**"。
一旦允许实现者批准自己的实现，审查就退化为自我确认 —— 这属于**降低对风险的防护**。

**行为：** 永远生效，不受层级影响；**只能被增强，不能被削弱**；冲突时一律采用**更严格**的一方。

### 轴 B — 特化轴

```
② Workspace / 中央规范   （最一般，提供默认值）
③ 项目规则                （覆盖 ②）
④ 任务规则                （覆盖 ③）
⑤ 目录级规则              （覆盖 ④）
⑥ 当前任务上下文          （最具体）
```

---

## 3. 最终优先级

```
① 受保护规则（Protected）      ← 绝对优先，不可削弱
        ▼
② 中央公共规范                 ← 通用默认值
③ 项目规则                     ← 覆盖 ②
④ 任务规则                     ← 覆盖 ③
⑤ 目录级规则                   ← 覆盖 ④
⑥ 当前任务上下文               ← 覆盖 ⑤
```

**读法：** 先检查是否有受保护规则适用。若无，在 ②–⑥ 中取**最具体**的一层。

---

## 4. 冲突裁决算法

```
给定冲突 C：
  1. C 是否涉及 security / safety / system 约束？
        是 → 采用更严格的一方。结束。
  2. C 是否涉及受保护规则（git §6 / quality 测试禁止 / permissions P3 / change-safety）？
        是 → 采用受保护规则。结束。
  3. 否则 → 采用层级更具体的一方（② < ③ < ④ < ⑤ < ⑥）。
  4. 仍无法判定？
         → 停止。记录冲突（含双方原文与出处），请求人类裁决。不得自行猜测。
```

## 5. 增强 vs 削弱

| 变更 | 判定 |
|---|---|
| 项目要求"所有变更需双人 Review" | ✅ 增强 |
| 项目要求"本项目禁用某类危险 API" | ✅ 增强 |
| 项目要求"本项目密钥可硬编码以便测试" | ❌ 削弱 |
| 任务要求"跳过测试以加快交付" | ❌ 削弱 |
| 目录规则要求"此目录允许 force push" | ❌ 削弱 |

**判定原则：** 若变更**减少**了对某项风险的保护 → 削弱 → 拒绝。

---

## 6. 声明覆盖的方式

覆盖必须**显式声明**，不得隐式覆盖。

项目 `AGENTS.md`：

```markdown
## Project-specific Rules
- [覆盖] quality.md §一.4：本项目允许在测试中使用魔法值。
- [补充] 所有 API 必须返回 RFC 7807 格式错误。
- [增强] 所有变更需通过安全扫描。
```

任务文件：

```markdown
## Task Rules
- [覆盖] 本任务临时放宽 lint 规则 X（原因：...）。
```

**未显式声明的覆盖一律无效。**

---

## 7. 规则定义者的义务

- **单一事实来源**：一条规则只在一处定义，其他位置引用而非复制。
- 修改规则时必须检查是否有引用方需要同步。
- 不得在公共规范里写具体技术栈规则。

---

## 8. 示例

**场景：** 公共规范要求提交信息用 Conventional Commits；某项目要求用中文描述。
→ 非受保护 → 走特化轴 → 项目更具体 → 采用项目要求（但仍保留结构前缀，因为前缀未被覆盖）。

**场景：** 某任务要求"为赶进度，先不写测试"。
→ 涉及 `quality.md` §二 §5（受保护）→ **拒绝**。若确实无法测试，须在任务记录中显式说明并获批准。
