# Rule: Security

> ⚠️ **受保护规则（Protected Rule）**
> 本文件属于**约束轴**规则。任何 Project / Task / 目录级规则**不得削弱**本文件的任何约束，
> 只能**增强**。冲突时一律采用**更严格**的一方。

---

## 1. 最小权限原则

- Agent 与代码都只应拥有完成任务所必需的最小权限。
- 默认拒绝（deny by default），按需显式授权。
- 不扩大权限以"方便实现"。

## 2. 敏感信息

**绝对禁止**出现在代码、日志、提交、文档中的内容：

| 类别 | 示例 |
|------|------|
| 凭据 | 密码、API Key、Token、私钥、证书 |
| 个人数据 | 身份证号、手机号、地址、生物特征 |
| 生产配置 | 数据库连接串、生产端点、内部主机名 |

**正确做法：**

- 通过环境变量或密钥管理服务注入。
- 提交前用扫描工具检查。
- 若已泄露 → **立即轮换**（仅从历史中删除是不够的）。

## 3. 输入校验

- **所有外部输入都不可信**：用户输入、API 请求、文件内容、第三方响应。
- 在系统边界处校验：类型、长度、范围、格式、白名单。
- 禁止将未校验的输入拼接进查询、命令、路径、模板（防注入）。

## 4. 认证与授权

- 认证（你是谁）与授权（你能做什么）必须分离。
- 每个受保护操作都必须校验授权，不得依赖前端隐藏。
- 会话/令牌必须有合理的过期与失效机制。

## 5. 依赖与供应链

- 引入依赖前评估：维护状态、已知漏洞、许可证、体积。
- 锁定依赖版本；使用锁文件。
- 定期更新并扫描已知漏洞。
- 禁止从未知来源安装依赖。

## 6. 数据保护

- 传输加密（TLS）。
- 敏感数据静态加密。
- 最小化收集与保留。
- 删除必须彻底（含备份策略的明确说明）。

## 7. 日志安全

- 日志不得包含凭据、令牌、个人数据。
- 错误信息对外不得泄露内部实现细节（堆栈、路径、版本）。
- 记录安全事件（登录失败、权限拒绝、异常访问）。

## 8. 高风险操作（需额外约束）

以下操作属于**高风险**，必须按 `.agents/protocols/change-safety.md` 执行：

- 删除数据 / 删除文件
- 数据库迁移 / 结构变更
- 修改生产环境
- 修改安全策略
- 修改基础设施
- 大规模重构
- destructive Git 操作

## 9. 默认安全姿态

| 维度 | 默认值 |
|------|-------|
| 访问控制 | 拒绝 |
| 输入 | 不可信 |
| 数据 | 加密 |
| 日志 | 脱敏 |
| 依赖 | 锁定并扫描 |
| 权限 | 最小 |
| 失败 | 关闭（fail-closed），不失败开放 |

## 10. 安全问题处理

发现安全问题时：

1. **立即停止**相关变更。
2. 评估影响范围与严重程度（见 `.agents/roles/security.md` 分级）。
3. 不公开披露细节（在修复前）。
4. 修复后验证并记录。
